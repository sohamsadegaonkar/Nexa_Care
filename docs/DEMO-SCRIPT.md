# Nexa Care V2: Security Sprint Demo Script

**Duration:** 10 Minutes
**Setting:** Live staging environment with two physical devices.
**Requirement:** 1 Doctor Tablet (logged in as `clinician`), 1 Patient Phone (logged in as `patient`, push registered).

---

## Scene 1: Context & Architecture (2 min)
*Goal: Orient the audience to the trust chain.*

1. **Presenter:** "Welcome. Today we demonstrate the hardened Nexa Care V2 identity and consent layer. We've moved from 'blind trust' to 'cryptographic proof' for every access decision."
2. **Action:** Briefly show a diagram (or describe) the three-way handshake:
   - **Doctor:** Requests access via NFC scan.
   - **Patient:** Approves asynchronously via Biometric Push.
   - **Backend:** Verifies signatures and issues a single-use scoped token.
3. **Key message:** "Access is only granted when the patient's device signs a unique challenge generated by the doctor's request."

---

## Scene 2: The Happy Path (3 min)
*Goal: Demonstrate the core "Push Biometric" assurance flow.*

1. **Doctor Action:** On the tablet, tap the NFC card of the patient.
2. **Doctor Action:** Select "Routine Checkup" as the purpose. Tablet screen transitions to "Waiting for Patient Approval" with a pulsing spinner and countdown.
3. **Patient Action:** Phone buzzes. "Access Request: Dr. Integration at Hospital One".
4. **Patient Action:** Tap notification. View details (Clinician, Hospital, Purpose).
5. **Patient Action:** Tap **Approve**. A Face ID / Fingerprint prompt appears.
6. **Patient Action:** Authenticate. Screen shows "Approved - Access Granted".
7. **Doctor Observation:** The tablet **automatically** flips from the waiting screen to the decrypted Patient Record.
8. **Explanation:** "In the background, the patient's device signed a cryptographic nonce. The backend verified this signature against the per-patient DEK before unlocking the record."

---

## Scene 3: Deliberate Failure (2 min)
*Goal: Prove the system fails closed.*

1. **Doctor Action:** Initiate a second request by scanning another card.
2. **Patient Action:** Receive notification. Tap it.
3. **Patient Action:** Tap **Deny** on the phone.
4. **Doctor Observation:** Tablet immediately updates to a red screen: "Access Denied — Patient refused consent."
5. **Doctor Action:** Try to "refresh" or bypass.
6. **Explanation:** "There is no override. The assurance check failed on the server. Without a valid 'Approved' record in Redis, the consent engine refuses to issue a token."

---

## Scene 4: Break-Glass & Erasure (2 min)
*Goal: Show the safety valves and privacy controls.*

1. **Doctor Action:** Tap "Emergency: Break-Glass" on the tablet.
2. **Doctor Action:** Enter a mandatory reason code (e.g., `UNCONSCIOUS_PATIENT`).
3. **Observation:** Full access is granted.
4. **Explanation:** "Break-glass bypasses push approval but elevates auditing. We can also revoke these grants immediately."
5. **Admin Action (on a separate laptop/screen):** Trigger "Cryptographic Erasure" for this patient.
6. **Doctor Action:** Try to read the record again.
7. **Observation:** Tablet shows: "Error: Patient Data Erased (410 GONE)".
8. **Explanation:** "PII is now mathematically gone. The key was destroyed. Clinical data remains but is now fully anonymous."

---

## Scene 5: The Audit Trail (1 min)
*Goal: Prove accountability.*

1. **Action:** Open the system audit log (CLI or Admin View).
2. **Observation:** Show the sequence: `PUSH_REQUEST_CREATED` → `PUSH_RESPONSE_RECEIVED` → `BIOMETRIC_VERIFICATION_SUCCESS` → `CONSENT_CONSUMED`.
3. **Action:** Highlight a `record_hash`.
4. **Final Word:** "Every action is linked in an immutable chain. If any record is tampered with, the entire chain breaks. This is Nexa Care V2: Security by proof, not policy."
